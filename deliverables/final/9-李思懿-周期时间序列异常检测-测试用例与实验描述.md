# 测试用例与实验描述

第 9 组：李思懿（组长）、翁汇坤

## 1. 实验目标与范围

使用 NAB 的 21 条真实序列，检验周期点检测、稳健预测和快慢证据融合能否减少异常告警中的误报。输入共 223,878 点，其中测试段 89,559 点、22 个官方异常窗口。序列覆盖云监控、已知原因数据和推文计数三类场景，全部结构合格序列均纳入。

准确性实验在相同时间划分、标签和事件评价规则下比较四个外部 baseline、三个单路组件和三个融合方案。另检验 IoTDB 内外评分组件的一致性和执行成本。最终融合在 Python 中完成；生产 Java/UDF 提供已有周期、EWMA 和稳健 AR 组件。

## 2. 环境与解压

实验环境为 Java 17、Maven 3.9.x、IoTDB 2.0.11 树模型、Python 3.12。数值依赖固定在 `requirements-lock.txt`，文档生成依赖在 `requirements-docs.txt`。已提供最终 PPT、DOCX 和 PDF，复现检测不需要安装文档生成依赖。

把“代码与数据”和“实验结果”两份 ZIP 解压至同一个普通本地目录，合并得到 `dw-periodic-ad/`。不要在云盘中编译、拟合模型或启动数据库。代码包附带本次使用的 Runner 与 UDF JAR；离线效果复现不需要 IoTDB。

```bash
cd dw-periodic-ad
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
```

Windows 可将 `.venv/bin/python` 换成 `.venv\Scripts\python.exe`。shell 脚本及数据库部署已验证的环境为本项目 macOS 本机环境。

预期输出为 `results/reproduced-submission/verification.json`：

| 字段 | 预期值 |
| --- | --- |
| status | matched |

## 5. 数据和校准协议

### 5.1 数据来源与筛选

NAB 固定版本为 `ea702d75cc2258d9d7dd35ca8e5e2539d71f3140`，原始文件、官方标签、许可证和哈希均随包提供。47 条真实候选按以下规则筛选：数值有限；时间戳唯一、严格递增且形成完整规则网格；步长能整除一天；训练段至少满足 4 个日周期加 1 个点。纳入 21 条，排除 26 条，完整原因见 `附录/候选序列与来源.csv`。不插值、不去重修补、不按真实标签或得分删序列。

按原始时间顺序划分前 40% 训练、中间 20% 校准、后 40% 测试。周期从日/周候选中，仅按训练相关性和可用历史确定。原纽约出租车日期划分案例曾有 5 个测试窗口；本轮统一 40/20/40 下该序列有 4 个，不能混计。

### 5.2 选参

三套校准注入分别为短脉冲、持续偏移和平线，每套 6 个。注入尺度由训练数据计算，注入不改变真实标签。每种方法独立选择参数和阈值：在背景点报警目标 0.5%、约每 14 天一次的事件预算以及注入窗外点报警目标 1% 的约束下，优先提高三套平均事件 F2；回退与超额情况保留在选择记录中。

最终融合仅有两种预设：自适应分支与慢速周期 EWMA 融合，或与快速周期点分数融合。两路按各自验证阈值归一化后等权平均。最终阈值不低于 1，只按验证背景预算上调；模式按校准注入指标选择，不按测试得分逐条挑选。

NAB 已参与方法开发。虽然逐序列拟合和选参不使用真实测试标签，最终成绩仍属于已暴露数据上的开发比较，不作为新盲测。

### 5.3 统一指标

| 指标 | 约定 |
| --- | --- |
| 事件合并 | 在完整评分历史上按 1 小时间隔合并，按事件起点归属 |
| TP / FN | 窗口内首个可归属事件为 TP；未命中窗口为 FN |
| FP | 窗口外事件和窗口内重复事件之和 |
| F1 | 2TP / (2TP + FP + FN) |
| 点级 FPR / AP | 直接使用官方窗口内外标记，不作 point adjustment |
| 窗口分数比 | 窗口内最高分除以冻结阈值，不是异常概率 |

官方窗口是较宽的异常评价范围，点指标只是窗口代理；不能据此断言物理异常持续时间。某窗内存在正标记，但事件从窗前延续而来时，也可能没有新的可归属 TP。该口径不是 NAB 官方带早检奖励的分数。

## 6. 既有检查与测试用例

本次以实验和材料交付为主，复用既有有效检查，不另建一套测试门禁。

| 用例类别 | 检查内容 | 实际证据 |
| --- | --- | --- |
| 热身和因果顺序 | 历史不足不评分；先评分后更新；未来不改变过去 | 既有 Java 核心用例 |
| 常量与数值边界 | MAD 下界、非有限值、浮点回读 | 既有数学与边界用例 |
| 周期与限幅证据 | 相位状态、有界更新、EWMA 输入限幅 | Java 核心与适配用例 |
| 稳健 AR | 固定系数、残差/水平历史、缺口后重热身 | 专项用例与独立数值参考 |
| 文献 baseline | SR、Left-MP 手工例子、常量和前缀不变性 | 7 项数学/因果用例通过 |
| UDF 与实例状态 | 参数、输出类型、四种 mode、状态隔离 | 83 项相关 Java 用例通过 |
| 原行为兼容 | 原五类方法，120 场景 × 200 输入 | 含标题 24,120 行逐字节一致 |
| 最终交付回放 | 21 条重新选模式、融合、计算 11 项指标 | 231 项与归档结果一致 |

83 项 Java 记录来自对应实现工作区；主仓相应源码已逐文件核对，随后打包并完成默认兼容回放。不是声称本次又运行了一遍全量测试。原始记录位于 `results/iteration2/java/`。


## 7. 库内外实验

真实 IoTDB 对照包括一个稳健 AR 示例和一个周期示例，分别有 3,168、8,976 个有效评分点。score、flag、event、active 四种独立单列输出逐行一致，两次查询一致，最大绝对误差为 0。

性能实验对同一个冻结 AR 模型，把公开 NAB 序列沿时间网格平铺到 1 万、10 万、100 万点。平铺仅生成成本负载，不增加精度实验的数据规模。比较 SQL UDF 与取原值后运行同一 Java 核心；预热 2 轮、交替测量 5 轮，计时至完整消费结果，排除导入和文件写出。

| 输入点数 | UDF 中位数/ms | 库外同核心/ms |
| --- | --- | --- |
| 10,000 | 153.8 | 124.0 |
| 100,000 | 1,240.4 | 1,205.0 |
| 1,000,000 | 13,011.1 | 11,895.0 |

三规模输出校验和全部一致。该实验没有显示 UDF 加速，测量对象是 AR 组件，不包含 Python 融合总时延。原始逐轮数据位于 `results/iteration2/database/performance/`。

配置好本机 IoTDB 并部署本项目 UDF 后，可运行：

```bash
source scripts/env.sh
.venv/bin/python scripts/benchmark_adaptive_database.py --output results/local-ar-performance
```

该命令创建本项目专属性能设备，不删除已有数据。不要指向生产数据库。数据库安装和部署命令见代码包 README。

## 8. 结果索引和边界

`附录/逐序列对比.csv` 含 21×10=210 行；`附录/逐窗口对比.csv` 含 22×10=220 行。10 项包括 3 个单路、3 个融合方案和 4 个外部 baseline。逐窗给出原边界、命中、首警、最高分、阈值及比值；来源附录给出论文 DOI、实现区别和原数据链接。

最终融合事件 F1 为 0.5172，高于本轮四个外部 baseline。相对单路自适应方法，命中总数仍为 15、误报从 43 降到 21，但两者命中的具体窗口并非完全相同。最终方法点级窗口外 FPR 高于单路自适应；已知原因子组也未领先 Left-MP。全体和各子组结果均保留，结论限定为本轮 NAB 多场景实验。
