## 1. 测试用例

### 1.1 测试组织与执行方式

测试用例分为 Java 单元测试与 Python 数值测试，分别位于各模块 `src/test/` 与仓库 `tests/` 目录；兼容性回归与归档重算依靠仓库脚本完成。所有结论均来自实际执行记录，助教无需重复执行，如需复核可按下列命令运行。

```bash
mvn test                                          # Java 核心算子与 UDTF 测试
.venv/bin/python -m pytest tests                  # Python 评价与基线数学测试
bash scripts/check_default_compatibility.sh       # 默认配置兼容性回归（需先 mvn -DskipTests package）
.venv/bin/python scripts/reproduce_submission.py  # 基于归档分数的指标重算
```

### 1.2 覆盖范围与结论

| 验证类别 | 覆盖内容 | 规模与结论 |
| --- | --- | --- |
| 核心算子边界与因果性 | 先评分再更新的顺序、热身期抑制、MAD 常量序列下界保护、时间戳缺口与 NaN/Inf 处理 | 指定 83 项相关 Java 测试全部通过 |
| UDTF 状态与模式隔离 | 多序列独立实例隔离、四种输出 mode 行为一致 | 含于上述 83 项 Java 测试，全部通过 |
| 外部基线数学对齐 | SR、Left-MP 因果尾窗实现与数学定义对齐 | 7 项文献数学测试全部通过 |
| 默认配置兼容性回归 | 原有 5 种检测方法在 120 个场景 × 200 个输入点上的前向兼容与输出稳定 | 默认输出完全一致 |
| 归档数值重算一致性 | 基于离线归档结果重选 21 条序列模式并重算指标 | 21 序列 × 11 项指标共 231 个数值完全一致，稳定选出 18 慢 3 快 |

### 1.3 关键测试点

1. **因果顺序**：每个时刻必须先输出评分、再以该观测更新同相位缓存与全局残差窗口，测试覆盖“顺序颠倒即产生未来信息泄漏”的场景。
2. **热身与退化输入**：热身长度不足时不输出评分；常数序列在上、下界保护下不产生除零或无穷分数；含缺口、重复时间戳与 NaN/Inf 的输入按约定处理。
3. **状态隔离**：同一 UDTF 查询内多条序列互不影响；单实例无全局状态，重复查询结果稳定。
4. **四模式一致性**：`score`、`flag`、`event`、`active` 四种输出模式下，库内查询与库外同一 Java 内核逐行一致。
5. **基线数学对齐**：Spectral Residual 与 Left-MP 的因果尾窗实现按论文公式逐点核对，避免误用未来观测。
6. **前向兼容**：原有 5 种检测方法在 120 个场景（序列形态 × 参数组合）× 200 个输入点下输出与改造前完全一致。
7. **归档重算**：由离线归档分数重选模式并重算指标，21 条序列 × 11 项指标仍为 231 个一致数值。

### 2.2 数据与划分

采用 NAB 官方提交 `ea702d75cc2258d9d7dd35ca8e5e2539d71f3140`，按确定性规则从 47 条真实候选序列中筛选出 21 条，合计 223,878 个实测点；每条序列按时间顺序切分为 40% 训练段、20% 验证校准段与 40% 测试段（测试段共 89,559 个实测点）。异常标签直接使用上游 `combined_windows.json` 官方窗口，与测试段相交共 22 个窗口。

### 2.3 参评方法与选参

实验评测 10 种方法：周期点检测、慢速周期 EWMA、自适应分支 A、固定快速融合、固定慢速融合、最终快慢自适应融合，以及 Isolation Forest、LOF、Spectral Residual、Left-MP 四种文献基线。逐序列参数与快慢模式仅由训练段和验证校准段确定，在读取测试标签前冻结保存。

### 2.4 校准协议与评价口径

训练与验证不读取真实异常标签；校准段构造短脉冲（1/2/4 点）、持续偏移与常数平线三套合成异常，各含 6 处固定注入，在背景报警目标 ≤ 0.5%、背景合并事件约每 14 天 1 次、注入窗外点报警目标 ≤ 1% 的预算下，按三套注入的平均事件 F2 选定配置。评价时将间隔 1 小时以内的报警合并为事件，每窗首次命中计 TP、同窗重复与窗外事件计 FP、未命中窗口计 FN，报告事件级 P、R 与 F1（非官方 NAB 加权分数）。完整表述见说明文档 3.1 节。

### 2.5 环境与复现步骤

环境为 Java 17、Maven 3.9.x、Python 3.12，主实验纯离线，不启动 IoTDB；数据库端实验使用 IoTDB 2.0.11 Tree 模型。在仓库根目录依次执行：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
mvn -DskipTests package
.venv/bin/python scripts/prepare_expanded.py --download
.venv/bin/python scripts/run_submission_experiment.py
```

`--download` 拉取并锁定上述 NAB 提交，仓库不保存原始数据；若已存在 `results/iteration2/final-nab/selection.json`，完整实验入口拒绝覆盖，需在新克隆目录重跑。若工作区已有 `results/submission/nab-replay` 归档，可用 `.venv/bin/python scripts/reproduce_submission.py` 直接重选模式并重算指标。

### 2.6 结果摘要

最终快慢自适应融合在全量 21 条序列、22 个窗口上取得 TP/FP/FN = 15/21/7，事件 F1 = 0.517241（P = 0.416667，R = 0.681818），高于 4 种文献基线中最优的 Isolation Forest（13/28/9，F1 = 0.412698）；相对单路自适应分支 A（15/43/7，F1 = 0.375000）在保持同样命中窗口数的同时将事件误报从 43 次降至 21 次。库内 UDF 与库外 Java 在 3,168 点与 8,976 点序列上四种输出模式逐行一致；10k/100k/1M 点规模下库内耗时 153.8/1,240.4/13,011.1 ms，库外同内核耗时 124.0/1,205.0/11,895.0 ms。逐方法对比、消融分析、子集表现与局限性讨论见说明文档第 3 节与第 4 节。
