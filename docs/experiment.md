# 实验约定（实施前草案）

本文件整理实施说明中的预设约定。当前尚未运行异常检测、选参、事件评价或性能实验，不含检测指标；正式实验前确认并随配置冻结。

数据时间与划分以 configs/data-manifest.json 为准，标签闭区间，数据划分半开区间。所有方法从同一个训练历史起点独立重放，取分数后再选评价区间。

主方法先按 K∈{3,4,6}、c∈{2,3,5}、τ∈{3,4,5,6} 形成最多 36 组周周期候选；P=336，P=48 只做预先规定的敏感性分析，不按测试结果挑周期。尺度下限默认规则待与选题报告原文复核。标签不得进入核心或 UDF。

验证段没有真实标签窗口。按背景每日至多 0.5 件告警事件的预算限制误报，合成扰动仅作辅助；选定参数后用未经注入的训练/验证重放，再接真实测试。测试段不得回流选参。

评价：相邻告警间隔≤1 小时合并，以事件首次告警时间归属闭区间标签窗口。每窗口最早开始的告警计 TP，其他同窗口告警计 FP 并另列重复计数；窗口外告警计 FP；未命中窗口计 FN。跨边界延续不重新归属。Precision=TP/(TP+FP)，Recall=TP/(TP+FN)，F1=2TP/(2TP+FP+FN)，零分母记 0。必须保存全部 5 窗口逐项结果。窗口外告警率按窗口外总时长折算天数，最终应写清固定采样下的时长算法。这不是 NAB 官方加权评分。

基线：滑动 Z-score、滑动 MAD、固定周期检测器、直接更新周期检测器；主方法与机制消融对照直接更新、异常冻结、有界更新。仅修改目标机制，残差窗口更新规则与其他参数保持一致。

一致性门槛：相同输入、参数、历史范围与有效输出时间戳；分数满足 |a−b|≤1e−9+1e−8×max(|a|,|b|)，且无 NaN、漏点、乱序。当前透传查询的逐点相等不是未来异常分数一致性的替代证据。

性能：路径 A 从发起 UDF 查询到完整接收结果；路径 B 从发起原始值查询到同一 Java 核心完成评分。先做 JVM/查询预热，交替至少 5 次，保存每次和实际返回行数，报告中位数及离散程度；另测外部纯计算。不用 CSV 文件大小替代传输字节，不编造数据库内纯算法耗时。先主序列，再 10 万/100 万点合成规模数据。

正式运行保存 run_id、Git commit、工作区状态、数据 SHA-256、完整配置、种子、命令、开始/结束时间与退出状态；scores.csv、events.csv、metrics.json、timings.csv 各自分开。当前只有前期准备证据，没有这些尚未实施的检测产物。
